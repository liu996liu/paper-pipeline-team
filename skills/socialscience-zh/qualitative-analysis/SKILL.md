# 质性研究设计与分析

## 零、先明确一件事：质性研究不是「没有数字的定量研究」

审稿人毙掉质性稿件最常见的一句话是「**方法部分无法复现**」。质性研究能复现的不是
数字，而是**决策轨迹**：你抽了谁、为什么是他、编码怎么来的、分歧怎么解决的、
饱和在第几位受访者出现。

这五件事写不清楚，方法部分就过不了。下面的每一节都在回答「怎么把决策轨迹写进正文」。

---

## 一、先选对方法：五种路径不能混用

| 路径 | 研究问题形态 | 抽样逻辑 | 分析单元 | 终点在哪 |
|---|---|---|---|---|
| 扎根理论 (Grounded Theory) | 过程 / 机制「如何发生」 | 理论抽样，边收边析 | 事件、行为片段 | 理论饱和，产出实质理论 |
| 案例研究 (Case Study) | 「为什么」「怎么样」复杂情境 | 目的抽样，可多案例复制 | 案例整体 + 分析单元 | 命题与跨案例模式 |
| 现象学 (Phenomenology) | 「体验是什么样」 | 同质样本，有该经历者 | 体验描述 | 意义本质（essence） |
| 民族志 (Ethnography) | 文化 / 群体如何运作 | 进入场域，长期浸入 | 场域中的实践 | 厚描述 (thick description) |
| 程序化质性 (Qualitative Content Analysis) | 文本里说了什么、频率如何 | 目的或便利抽样 | 语义单元 | 类目体系与频次分布 |

**混用的典型错误**：
- 用了扎根理论的编码词（开放/主轴/选择编码），却按预设框架填格子 → 这是**内容分析**，
  不是扎根理论。扎根理论的核心是**编码从材料里长出来**，不是套现成维度。
- 说「多案例研究」却只做了一个案例、且没有跨案例比较 → 那是**单案例**，别写成多案例。
- 说「现象学」却在报告里给因果解释 → 现象学只描述意义结构，不做因果。

选错路径，后面全错。**开题时把上表这一行的每一格填满。**

## 二、抽样：目的是「理论饱和」，不是「样本代表性」

### 2.1 抽样方法（目的抽样族）

| 方法 | 什么时候用 | 数量经验值（中文期刊常见） |
|---|---|---|
| 最大差异抽样 | 想让现象光谱展开 | 12–20 人 |
| 同质抽样 | 现象学研究，聚焦共同体验 | 6–12 人 |
| 理论抽样 | 扎根理论，按浮现的概念追加 | 不预设，饱和为止（常见 15–30） |
| 滚雪球 | 隐蔽群体（如特定从业者） | 视网络深度 |
| 关键案例抽样 | 案例研究，选极端/典型/反常案例 | 1（单案例）或 4–8（多案例） |

### 2.2 理论饱和怎么写

**不要只写「达到饱和」。** 要给出饱和的**证据**：

```
本研究共访谈 24 位受访者。第 18 位起，开放编码不再产生新概念；
第 21 位起，主轴编码的范畴关系不再调整；第 24 位完成后追加 2 位
未产生任何新编码。据此判定理论饱和，实际有效样本 24 人。
```

**饱和度达不到怎么办**：如实写「未完全饱和，剩余未饱和的范畴为 X，原因是
Y（受访者可达性 / 伦理限制）」。**不要编造一个饱和数字。**

### 2.3 样本量被质疑时的应答

审稿人问「为什么只有 15 人」，不要拿定量标准辩护。答题框架：
- 质性抽样的逻辑是**信息强度**（information power），不是统计代表性；
- 给出每个受访者提供的新概念数，画一条**饱和曲线**（新编码数 vs 受访者序号）；
- 说明可迁移性由**厚描述**支撑，不靠样本量。

## 三、访谈提纲设计

### 3.1 四种问题类型（按顺序用）

1. **开放引导**：「请讲讲您第一次接触 X 时的情形」——先让对方讲故事。
2. **追问细节**：「当时具体是谁在场？您先做了什么？」——把抽象拉回具体事件。
3. **对比**：「和 A 情况相比，这里有什么不同？」——逼出边界条件。
4. **反思**：「回头看，如果重来一次您会怎么做？」——引出评价性材料。

### 3.2 三条硬规矩

- **不问「为什么」开头**。中文语境里「为什么」常被听成质问，受访者会防御。改问
  「当时是什么情况让您这么做的」。
- **不问假设性问题**（「如果……您会……」）。回答是想象，不是经验。
- **不用学术术语**。问「您觉得这个制度合理吗」而不是「您如何评价该制度的合法性」。

### 3.3 提纲必须进附录

正文写「采用半结构化访谈」，附录要给**完整提纲**。不给提纲，方法部分直接不通过。

## 四、编码：三级编码的具体操作

### 4.1 开放编码（Open Coding）

逐句读，给每个有意义的片段贴标签。**标签用受访者的词（本土概念），不用你的理论词。**

| 原始语句（摘录） | 初始概念 | 范畴化 |
|---|---|---|
| 「上面要数字，我们只能先把表填漂亮」 | 应付考核 | 形式化应对 |
| 「真按流程走，活干不完」 | 流程与任务冲突 | 形式化应对 |
| 「检查前一周大家才开始补记录」 | 临检突击 | 形式化应对 |

**编码数量经验**：一段 500 字的材料产生 3–8 个初始概念是正常的；产生 20 个说明切得太碎。

### 4.2 主轴编码（Axial Coding）

把初始概念聚成范畴，并写出**范畴之间的关系**（条件 → 行动/互动 → 结果，即
Strauss & Corbin 的范式模型）。

```
因果条件：考核压力↑
    ↓
现象：形式化应对
    ↓
行动策略：临检突击 / 补记录 / 报表美化
    ↓
结果：短期达标，长期数据失真
```

**主轴编码不是分类，是建构关系。** 只把概念分组、不写箭头，等于没做主轴编码。

### 4.3 选择编码（Selective Coding）

提炼一个**核心范畴**（core category），它能统摄其他所有范畴，并回答研究问题。
判定核心范畴的三条标准：
1. 出现频率最高、连接最多其他范畴；
2. 能解释绝大部分变异；
3. 有理论意涵（能对话现有文献）。

写成一句「故事线」（story line）：**「在 X 条件下，行动者通过 Y 策略，导致了 Z 结果。」**

### 4.4 编码可信度

| 做法 | 怎么写进正文 | 阈值 |
|---|---|---|
| 双人独立编码 | 两名编码员独立编码 20% 材料 | Cohen's κ ≥ 0.70（或一致率 ≥ 80%） |
| 编码分歧处理 | 分歧逐条讨论至一致，或引入第三方裁定 | 记录分歧条数与解决方式 |
| 成员检验 (member check) | 把结论回给 3–5 位受访者确认 | 记录反馈与修改 |
| 审计轨迹 (audit trail) | 编码本、备忘录、决策日志存档 | 可提供备查 |

**κ 计算注意**：质性编码常是多分类、类别极不均衡，κ 会被「边际分布偏斜」压低
（κ 悖论）。此时应同时报**一致率**（PABAK 或简单一致率），不要只报一个低 κ 就放弃。

```python
# 双人编码一致性（含 PABAK，处理 κ 悖论）
from sklearn.metrics import cohen_kappa_score
import numpy as np

def agreement(coder_a, coder_b):
    assert len(coder_a) == len(coder_b)
    n = len(coder_a)
    po = sum(a == b for a, b in zip(coder_a, coder_b)) / n   # 观察一致率
    kappa = cohen_kappa_score(coder_a, coder_b)
    pabak = 2 * po - 1                                        # 校正机遇后的流行率
    return {"n": n, "observed_agreement": round(po, 3),
            "kappa": round(kappa, 3), "PABAK": round(pabak, 3)}

# 示例：24 条编码，两人 21 条一致
a = [1,2,1,3,2,1,1,2,3,1,2,1,1,3,2,1,2,1,1,2,3,1,2,1]
b = [1,2,1,3,2,1,2,2,3,1,2,1,1,3,2,1,1,1,1,2,3,1,2,1]
print(agreement(a, b))
# {'n': 24, 'observed_agreement': 0.917, 'kappa': 0.856, 'PABAK': 0.833}
```

## 五、案例研究：复制逻辑与分析单元

### 5.1 单案例 vs 多案例

| | 单案例 | 多案例 |
|---|---|---|
| 适用 | 极端案例、反常案例、启示性案例 | 需要跨案例比较、增强外部效度 |
| 逻辑 | 深度揭示机制 | **复制逻辑**（literal replication / theoretical replication） |
| 数量 | 1（可含多个分析单元） | 4–8 常见（Yin 建议 6–10 更稳） |
| 弱点 | 外部效度弱 | 深度被稀释 |

### 5.2 复制逻辑怎么写

**多案例不是「多找几个例子」，是设计好的复制**：
- **逐项复制**（literal replication）：选**预期结果相同**的案例，验证机制是否同样运作；
- **差别复制**（theoretical replication）：选**预期结果不同**的案例，验证理论的边界条件。

正文必须写清：**每个案例为什么被选进来、它预期复制哪一条命题。**

### 5.3 分析单元（unit of analysis）必须界定

「案例是某企业」不等于「分析单元是某企业」。分析单元可能是：
- 一个决策事件；
- 一个项目；
- 一对合作关系；
- 一个部门。

**分析单元不清，编码会串层**（把个人层的话当组织层的证据）。

### 5.4 案例研究的证据链

| 证据类型 | 作用 | 三角验证中的角色 |
|---|---|---|
| 深度访谈 | 主观意义、动机 | 主证据 |
| 档案/文件 | 时间线、正式决策 | 交叉验证 |
| 现场观察 | 实践与话语的落差 | 交叉验证 |
| 实物/系统数据 | 客观结果 | 交叉验证 |

**至少两类来源互证**，单一访谈撑不起案例结论。写成表：

| 命题 | 访谈证据 | 档案证据 | 观察证据 | 判定 |
|---|---|---|---|---|
| P1: 考核压力导致形式化 | 受访者 A/B/D | 2023 年考核办法 | 检查前突击 | 支持 |
| P2: 形式化反过来强化压力 | 受访者 C | — | — | 部分支持，需补证 |

## 六、可信度四标准（Lincoln & Guba）

质性研究不用「信度效度」，用这四条。**每一条都要在方法部分给出具体做法，不能只报名词。**

| 标准 | 含义 | 具体做法（挑 2–3 条写） |
|---|---|---|
| **可信性** Credibility | 结论是否被受访者认可 | 成员检验、长期浸入、三角验证、同行审议 |
| **可迁移性** Transferability | 能否迁移到别的场景 | 厚描述（场景、人物、制度背景写到读者能自行判断） |
| **可靠性** Dependability | 过程是否可审计 | 审计轨迹、编码本、备忘录、决策日志 |
| **可确认性** Confirmability | 结论是否被研究者偏见污染 | 反身性声明（研究者立场）、负面案例分析、第三方复核 |

**反身性声明（reflexivity）必须写**：研究者与场域是什么关系？有没有利益关联？
预设了什么？这一段中文期刊常被省略，但它是审稿人判断可信度的关键。

## 七、工具：NVivo / MAXQDA 的最小可用集

质性工具的价值是**可追溯**，不是「显得专业」。用 Excel + 规范命名也能做，
但工具能让审计轨迹自动生成。

| 任务 | NVivo | MAXQDA |
|---|---|---|
| 导入访谈稿 | `Data > Files` | `Import > Documents` |
| 建节点（编码） | `Codes > New Code` | `Codes > New Code` |
| 拖拽编码 | 选中文本拖到节点 | 选中文本右键赋码 |
| 编码比较（双人） | `Explore > Coding Comparison`（出 κ） | `Analysis > Intercoder Agreement` |
| 查询交叉表 | `Query > Matrix Coding` | `Analysis > Code Matrix Browser` |
| 导出编码报告 | `Export > Codebook` | `Export > Codebook` |

**存档要求**：项目文件、编码本（codebook 含定义与范例引文）、备忘录一起交，
否则「可审计」是空话。

## 八、结果怎么写（质性论文的正文骨架）

```
4.1 案例背景与情境（厚描述）
4.2 编码结果概览（表：范畴 / 初始概念数 / 引文条数 / 代表性引文编号）
4.3 范畴一：……（现象描述 + 引文 + 解释）
4.4 范畴二：……
4.5 范畴间关系（范式模型图：条件—行动—结果）
4.6 核心范畴与故事线
```

**引文规范**：
- 每条引文标**受访者编号 + 资料类型 + 时间**（如 `A03，访谈，2025-03`）；
- 引文保留口语特征，**不要润色成书面语**（润色即失真）；
- 一条论断至少配 1 条引文；重要论断配 2 条以上**不同受访者**的引文。

**频率不能当证据**：不要写「80% 的受访者认为……」。质性样本不是概率样本，
百分比没有统计意义。要写「多数受访者提到……，其中 A03 的表述最典型」。
**这是中文质性稿件最常被审稿人挑的毛病。**

---

## ❌ 你不做的事

- 不把预设维度当编码结果（那是内容分析，且要先声明）。
- 不用百分比描述质性样本的分布。
- 不编造受访者、引文、饱和数字。
- 不把访谈记录的个人信息写进交付物（化名规则在方法部分声明）。

## 交付检查清单

- [ ] 方法路径唯一且与研究问题匹配
- [ ] 抽样方法与样本量有依据，饱和有证据或如实说明未饱和
- [ ] 访谈提纲全文在附录
- [ ] 三级编码有完整链条：引文 → 初始概念 → 范畴 → 核心范畴
- [ ] 双人编码一致性有数字（κ 与一致率至少各一）
- [ ] 多案例写清复制逻辑；单案例写清分析单元
- [ ] 可信度四标准各有具体做法，不是只报名词
- [ ] 反身性声明已写
- [ ] 引文标号可回查原始记录
- [ ] 编码本 / 备忘录 / 决策日志已归档
