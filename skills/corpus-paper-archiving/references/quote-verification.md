# 引文核验

读档里每一条引文都要能回到原文。凭记忆写的引文不是"略有出入"，而是**记忆重构加拼源**：它会自然地把两三处原文缝成一句通顺的话，读起来比原文还像原文。所以核验不是校对，是质检。

## 一、归一为纯汉字流

比较之前，把底本与引文都归一：

```python
han = lambda s: "".join(re.findall(r"[\u4e00-\u9fff\U00020000-\U0002ffff]", s))
```

**必须包含扩展区汉字**（`[\u3400-\u4dbf]` 与 `\U00020000-\U0002ffff`）。只用 `[\u4e00-\u9fff]` 会把「屬」「㐀」这类字滤掉，造成假阴性——曾因此把一批真引文误判为伪造。

这样一归一，标点、空格、页眉、版式噪声都被抹掉，剩下的就是"汉字序列是否相同"。这正是我们想要的：PDF 转文本一般不丢字，但几乎一定丢标点和断行。

## 二、两级判定

**第一级：整句命中。**`han(引文) in han(底本)`。命中即通过。

**第二级：8 字滑窗。**整句不中时，把引文切成长 8 汉字的滑动窗口，逐窗在底本里找，允许每两字之间插入 0–2 个杂字：

```python
pat = ".{0,2}".join(re.escape(c) for c in window)
```

统计命中窗口占比：

- 占比 ≥ 0.8 → **跨栏／跨行断裂**，引文成立，但要在读档里标一句"此处底本为双栏交错"或"跨页断行"；
- 占比 < 0.8 → **需回源改字或删除**。

为什么是 8 字：中文 6 字以内的短语偶合率太高（"所有权""法律关系"到处都有），8 字以上的连续偶合基本不可能。伪造引文的特征正是"最长只有 4–8 字能对上"。

## 三、用两种底本交叉

最好同时拿两份底本：PDF 直接抽取的纯文本，与（若有）PDF 转出的 Markdown。

- PDF 抽取件：读序正确，但可能把页眉页脚混进正文；
- Markdown 转出件：版式噪声多（按页插反引号、断行、字间空格），但字形对应准。

一份不中、另一份命中，说明是版式问题而非伪造。两份都不中，按需修处理。

## 四、双栏扫描件的特别处理

双栏排版会让同一视觉行内左右两栏的文字交替穿插，例如底本里出现：

```
……所有权是一种历史现象人鬼从自然宗教到礼教儒教的渐趋成型……
```

真实文本是"所有权是一种历史现象"，中间插进来的是另一栏的一句。这类引文**在整句比较里必然失败**，但在 8 字滑窗里会通过。

处置原则：引文保留（它确实是原文），但在读档里加一行说明该处底本为双栏交错，读者回查时不会以为你抄错了。

## 五、判定为伪造的特征

以下任一条成立即可判伪造：

1. 引文里有**底本中根本不存在的汉字**（字符存在性检查最硬，一条即确证）；
2. 最长连续可定位片段只有 4–8 字，且这些片段在原文中彼此不相邻；
3. 引文语义通顺但底本对应位置在讲别的事——这是"读懂了以后自己写的"。

处置：删除，或降为间接转述（"作者大意是……"），**不允许保留近似引文**。

## 六、批量核验的执行

```bash
# 单篇：列出该读档第七节每条引文的判定
python scripts/quote_check.py check _archive/03_xxx.md --src 底本/03_xxx.md --src2 _pdftxt/03_xxx.txt

# 全档：扫描目录内所有读档，只报需要处理的条目
python scripts/quote_check.py scan _archive --src 底本目录 --src2 _pdftxt
```

输出分三档：`精确命中`／`容噪命中（需加注）`／`需查`。**只处理第三档**，前两档不要动。

## 七、验收标准

- 精确命中率 90% 以上属正常（跨栏与断行会吃掉一部分）；
- "需查"条目必须逐条处理完毕，不许留到最后；
- 交付物里不写核验过程（不写"以上引文均经核对"），核验记录另存文件。

## 八、最常见的两种失败

**一、从成稿里反向抽引号去核。**中文引号成对出现时，正则会把整段散文当成一条引文捕出来，造成大量假失败。正确做法是**先写直接量清单**（要引哪些句子），逐条去核，而不是从成稿里抽。

**二、跨行处自己补字。**md 底本在换行处断句，写引文时顺手把两句接起来，接缝处多一个"的"或换一个词。这类引文在整句比较里必败，在 8 字滑窗里也只是刚好过关。**接缝处的字必须回底本看**，不许按语感补。
