# 中文文献获取规程（CNKI / 万方 / 维普）

> 结论先说：**知网没有公开 API，万方与维普也没有。** 任何声称「一条命令自动检索知网」的方案，
> 要么在爬、要么在冒充浏览器、要么已经失效。本文给出的是一条**能长期跑、不会封号、
> 证据链可回溯**的路线，以及明确不能碰的红线。

本文面向 `corpus-archivist`（t2 文献精读）与 `deep-researcher`（t3 深度调研），
其他成员涉及取文献时同样适用。

---

## 零、AI 能不能自己上知网？——不能，原因要讲清楚

这一段是 2026-10-28 的实测结果，不是猜测。**结论：即使作者有校园网 VPN 账号，
AI 也接不进去**，只能由作者本人检索、导出、把文件交给 AI 解析。

### 实测 1：直连知网被滑块挡在门外

```
curl https://kns.cnki.net/kns8s/brief/grid
→ 403  {"code":-403,"message":"https://kns.cnki.net/verify/home?captchaType=blockPuzzle..."}

curl https://kns.cnki.net/kns8s/defaultresult/index
→ 302  → https://kns.cnki.net/verify/home?captchaType=blockPuzzle&ident=d3624d...
```

### 实测 2：用真实浏览器（Edge + CDP）也一样

启动带 `--remote-debugging-port` 的 Edge，通过 DevTools 协议导航到知网检索页，
落地页是：

```
href : https://kns.cnki.net/verify/home?captchaType=blockPuzzle&...
title: 安全验证
正文 : 请完成安全验证 / 向右滑动完成验证
input: []            ← 连检索框都没有，页面上只有验证码
```

所以问题不在「怎么发请求」，而在**知网先要人过滑块，才肯给检索界面**。

### 实测 3：VPN 是给浏览器用的，不是给脚本用的

校园 VPN（Sangfor EasyConnect、Cisco AnyConnect、深信服 aTrust 一类）做的是**网络层隧道**，
它能让这台机器的浏览器走到「校内 IP」；但它同时有两个硬约束：

1. **登录要本人**：账号密码 + 短信/OTP 二次验证 + 首次绑定设备。AI 没有你的手机。
2. **改了隧道 ≠ 改了知网的判定**：知网除了看 IP，还看浏览器指纹、Cookie、滑块 token。
   过了隧道仍然会撞上滑块（实测 1 就是公网 IP，走隧道后是同一套前端）。

> 换句话说：**VPN 解决「能不能到」，滑块解决「是不是人」。后者 AI 过不去。**

### 实测 4：NCPSSD（国家哲社文献中心）曾是唯一半可用入口，但也不稳

2026-10-22 那次跑动里，`www.ncpssd.cn/searchHandler/search` 返回过可用题录
（见 `papers/sizheng-youth-green-lowcarbon/10-corpus/search-log.md` 第 51–52 行）。
2026-10-28 复测：同一接口返回 **HTML 落地页（9,592 B），不是 JSON**，POST/GET 都拿不到结构化结果。
→ 它已经变成需要前端 JS 渲染的页面，不能再当 API 用。

**结论：不要在任何文档或提示词里承诺「AI 会自己去知网查」。** 会写进 `verify` 的检查脚本，
就必须是能在没有网络的情况下跑通的东西。

## 一、为什么不能用脚本抓

| 做法 | 后果 |
|---|---|
| `requests` + 正则/`BeautifulSoup` 直打 `kns.cnki.net` | 接口签名与 `EXPRESS` 参数频繁变化，几天内失效；且属未授权访问，违反站点条款 |
| 复用浏览器 Cookie / 手动粘贴全局 Cookie | 账号绑定实名，泄露即封号；Cookie 过期后整个流程静默失败 |
| 第三方「知网 API」付费代理 | 无一有官方授权，来源不明，元数据质量不可控 |
| 绕过验证码（打码平台 / OCR） | 明确违规，学术机构账号风险最高 |

**已经失效、不要再装**（曾经常年被推荐，README 已自述失效或停止维护）：
`bughandler/cnki-downloader`、`itstyren/CNKI-download`、`yanzhou/CnkiSpider`（Python 2）、
`qiuqingyu/CNKICrawler`、`Arnie97/cnki-pdf`。

## 一点五、作者代理检索协议（这是实际会走的路）

既然 AI 进不去，就把分工写死：**作者负责「进得去」，AI 负责「读得懂」。**

### AI 交付物：一份可执行的检索作业单

每当流水线需要中文文献，`corpus-archivist` 必须先产出一份
`10-literature/cnki-request-<日期>.md`，内容必须包含：

1. **为什么需要**：这个缺口卡住了哪个任务、缺了会导致什么论证接不上；
2. **检索式**：`专业检索` 语法原文（`SU=` / `TI=` / `KY=` / `AU=` / `LY=` / `YE=`），可整段复制；
   同时给一份「高级检索界面逐行怎么填」的表，防止专业检索语法版本差异报错；
3. **筛选条件**：时间范围、来源类别（CSSCI / 北大核心 / CSCD）、文献类型、排序方式；
4. **纳入与排除标准**：什么样的算合格、什么样的明确不要（这一条最省作者时间）；
5. **需要几条**：给出下限与上限（如「3–6 篇」），不要写「越多越好」；
6. **每篇要什么字段**：默认要 RIS；如果某篇特别关键，再额外要 PDF。

### 作者交付物：导出文件

- 优先 **RIS**（跨工具最通用）；中文题录字段最全的是 **NoteExpress**；
- 存到 `paper/<slug>/10-literature/imports/cnki-YYYYMMDD-<主题>.ris`；
- **原样保留，不要先手工整理**——解析与去重是脚本的活，手工整理会丢字段；
- 忘记导出、只复制了参考文献列表也可以：GB/T 7714 格式的纯文本也能解析，但会缺摘要与关键词。

### AI 接手：一条命令解析

```bash
python scripts/cnki_ingest.py \
    --inputs paper/<slug>/10-literature/imports/ \
    --out    paper/<slug>/10-literature/
```

产出四个文件：

| 文件 | 用途 |
|---|---|
| `records.json` | 结构化题录，带预生成的 GB/T 7714-2015 引文，供 t2 建读档 |
| `records.md` | 人读清单，缺字段的条目打 ⚠ |
| `issues.md` | 质检报告：缺页码 / 缺卷期 / 缺 DOI / 疑似重复 / 年份可疑 |
| `sources.json` | 每个导出文件解析出几条，用于核对「导出是不是漏了」 |

**这套脚本不联网、不猜、不补。** 缺页码就写「缺页码（GB/T 7714 期刊条目必需）」，
由作者回题录页补。这是刻意的：编造一个看起来像真的页码，比留空危险得多。

## 二、推荐路线：人工检索 + 官方导出 + 本地解析

这是唯一**完全合规且长期可用**的路线。全程 4 步：

### 第 1 步：在知网用「专业检索」构造检索式

不要用一框式检索的结果直接导出——你无法复现它。用**专业检索**，把检索式原文存下来：

```
SU=('数字化转型' + '数字技术') AND SU=('绿色创新' + '低碳创新')
AND LY=('数量经济技术经济研究' + '中国工业经济' + '管理世界')
AND YE=2020-2026
```

- `SU` 主题、`TI` 篇名、`KY` 关键词、`AU` 作者、`FT` 全文、`TKA` 篇名+关键词+摘要、
  `LY` 来源刊、`YE` 年。
- 来源刊可直接写刊名；也可在左侧「来源类别」勾选 **CSSCI / 北大核心 / CSCD**。
- **检索式必须原样写进 `10-literature/search-log.md`**，附检索日期与命中数。
  这是可复现性的唯一凭据——别人拿着这句话能重现你的文献池。

### 第 2 步：导出为 RIS / NoteExpress / EndNote

勾选目标文献 → 导出 → 选 **RIS**（跨工具最通用）或 **NoteExpress**（中文题录字段最全）
→ 存到 `paper/<slug>/10-literature/imports/cnki-YYYYMMDD-<主题>.ris`。

导出时把**每页条数调到最大**再翻页，避免重复导出。

### 第 3 步：本地解析与去重

```bash
python scripts/cnki_ingest.py \
    --inputs paper/<slug>/10-literature/imports/ \
    --out    paper/<slug>/10-literature/
```

落成 `10-literature/records.json`（标题 / 作者 / 刊名 / 年 / 卷期 / 页码 / DOI / 摘要 / 关键词），
并同时给出 `records.md`（人读）、`issues.md`（质检）、`sources.json`（每个文件解析了几条）。
支持 RIS / EndNote `.enw` / NoteExpress `.net` / GB/T 7714 纯文本 / MEDLINE `.nbib`，格式自动嗅探。

去重规则按优先级：DOI 完全相同 → 标题+首作者+年 → 标题相似度 ≥0.92（仅提示，不自动合并）。
**不自动合并**是刻意的：两条看起来一样的题录，可能真是同一篇的两版（网络首发 vs 正式刊出），
也可能是两篇同题不同作者的文章。

### 第 4 步：补 PDF 与读档

PDF 只从**你有权限的渠道**取：机构订阅、作者主页、开放获取库、知网个人下载配额（在配额内正常下载是合规的）。
每一篇在 `10-literature/notes/` 建一条读档，缺页码的标 `待补`，**不得编造**。

## 三、可选的半自动增强（明确的风险边界）

如果检索量很大（数百篇），可以引入「真浏览器 + 人工过验证码」的半自动方案：

- 原理：用 Chrome DevTools 协议接管**你已登录的真实浏览器**，脚本只负责填检索式、翻页、点导出；
  一旦检测到验证码/滑块，**立即暂停并提示人工处理**，绝不尝试自动破解。
- 参照设计：`cookjohn/cnki-skills`（1021★，**仓库无 LICENSE，只能读设计不能拷代码**）
  的拆法值得学——10 个独立 skill 各管一件事（检索 / 高级检索 / 期刊目录 / 论文详情 / 导出），
  并且把「遇到滑块就停」写成硬约束。
- 技术参考：`SepineTam/cnki-mcp`（56★ GPL-3.0，作者明示仅限学习用途、不提供全文下载）。

**边界**：

1. 必须是你自己的账号、自己的浏览器会话；
2. 必须在人工在场时运行，检测到验证码即停；
3. 速率不能高于人手操作（建议 ≥6 秒/次，且每次会话不超过 100 条）；
4. 不得用于批量下载全文；
5. 一旦用到任何 AGPL 组件的代码，**只能调用，不能拷贝进本仓库**。

**做不到以上任意一条，就退回第二节的人工路线。**

## 四、其他中文源（都没有高星可用方案，只能人工）

| 源 | 自动化可行性 | 建议 |
|---|---|---|
| 万方 | 无可用开源方案（最高星项目 30★ 且 2017 年后停更） | 人工检索导出 RIS |
| 维普 | 同上 | 人工检索导出 |
| NCPSSD（国家哲学社会科学文献中心） | 无 | **免费全文，优先用**；人工下载 |
| PubScholar（中科院公益学术平台） | 无 | 免费，人工下载；`jasminum` 元数据源之一 |
| 百度学术 | 无可信方案 | 只用于找 DOI，再回原始库核对 |

> **NCPSSD 和 PubScholar 被严重低估**：大量中文社科论文在这两个平台有合法免费全文，
> 检索优先级应当是 **NCPSSD / PubScholar → 机构订阅 → 知网配额**，而不是默认打开知网。

## 五、元数据补全：中文 DOI 的坑

中文文献的 DOI 前缀指向不同注册机构，解析路径不一样：

```
10.3760/*  10.3969/*    → ISTIC（中国科学技术信息研究所）
10.13209/*              → CNKI
10.1360/*               → Crossref
```

用 `https://doi.org/api/handles/<doi>` 或 `https://doi.org/doiRA/<doi>` 先判断注册机构，
再决定去 Crossref 还是 ISTIC 取元数据。

**残酷的事实**：OpenAlex 只索引了约 37% 的中文核心期刊、约 24% 的中文文章；
Crossref 对多数 CSSCI 期刊的 ISSN 直接 404（实测 `1002-4921` 中国社会科学、
`1000-3894` 数量经济技术经济研究、`0439-8041` 学术月刊全部查无此刊）。

→ **所以任何「用 Crossref/OpenAlex 校验中文引文」的脚本，对 CSSCI 结构性失效。**
这类工具会把合法条目判成 `NOT FOUND`。本仓库的 `scripts/verify_paper.py citations`
只做**格式要素**检查（类型标识、年卷期页、URL），不做出处真实性判定——因为做不了。
真实性核验只能靠人工比对原文，或走第六节的清单。

详见 `skills/academic-research-skills/deep-research/references/chinese_literature_api_protocol.md`。

## 六、参考文献真实性的人工核验清单

每条要进参考文献的条目，逐条过这 6 问：

1. **这篇文献真的存在吗？** 能在知网/万方/NCPSSD 检索到题录，或在出版社页面找到。
2. **刊名全称对吗？** 「数量经济技术经济研究」不是「数量经济与技术经济研究」。
3. **年、卷、期、页码对得上吗？** 逐字抄自题录页，不要凭记忆补。
4. **作者顺序对吗？** 中文期刊多为「姓 名」，英文为「姓, 名首字母」。
5. **你引的那句话，原文真是这个意思吗？** 转述后的句子不许加引号当引文。
6. **页码能回查吗？** 给不出页码的直接引文标 `待核页码`，不得进综述。

**AI 最容易犯的错是第 1 条和第 3 条**：编造一个「看起来很像真的」的条目，
或者把页码四舍五入成整数。凡是无法在第 1 条上给出检索截图的条目，一律标 `unverified`。

## 八、给作者的一句话操作卡

> 当 AI 说「需要中文文献」时，它会给你一份带检索式的作业单。
> 你只要：**打开知网 → 粘检索式 → 勾选结果 → 导出 RIS → 丢进 `10-literature/imports/`**。
> 剩下的解析、去重、生成引文、标出缺什么，都是脚本的事。
> **不要手工整理题录**——手工整理会丢字段，而且丢的那个字段往往就是页码。
